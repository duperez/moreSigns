# Changelog

## 2.0.0 (Forge 1.20.1)

Port of the NeoForge 1.21.1 version of the mod to Forge 1.20.1 (47.3.0), Java 17, ForgeGradle 6. It is a new project: the branch starts from `origin/1.20.x` for history, but the source tree was replaced, not edited.

### Content
- Custom signs: a frame (border and post) plus a board (the plate you write on). Each part is a block id plus an optional dye tint, stored as item NBT (see Differences): the tag `Part` on frame and board items, the tag `SignParts` on sign items. The texture of a part is the texture of its block. Blocks `custom_sign` and `custom_wall_sign`; items `sign_frame`, `sign_board`, `custom_sign`. Drops keep the parts and pick block returns the right sign.
- Text color defaults once to white or black by contrast against the board's map color, tinted by the dye. Glass-like blocks without a map color count as light.
- Sign Workbench (`sign_workbench`), crafted shapeless from a crafting table and any sign (tag `minecraft:signs`). Four modes in tabs on the left of the panel: Make parts (1 block gives 1 frame or 2 boards, the block is consumed), Paint (a dye tints a frame or board and is not consumed; a wash button removes paint), Assemble (frame + board gives a sign), Take apart (sign gives frame + board with their colors; taking either result gives the other too; shift-click does a whole stack). Live rotating 3D preview, ghost icons and tooltips on empty slots, one hint line, shift-click support, 176x174 panel. UI reasoning is in `docs/workbench-ui-design.md`.
- Accepted materials are the block tag `moresigns:sign_materials`: planks, wool, terracotta, stone bricks, the 16 concrete blocks, bricks, nether bricks, quartz block, smooth stone, bone block, prismarine, cut copper, and the Forge tags `forge:storage_blocks`, `forge:glass`, `forge:stone`, `forge:cobblestone`, `forge:obsidian`. Blocks from other mods in those tags are accepted; a data pack can add more by editing the tag.
- The custom sign is deliberately not in the `minecraft:signs` item tag, so the workbench recipe cannot consume a customized sign.
- The creative tab lists the workbench, canvas, the 19 canvas signs, and sample frames, boards and signs for every planks plus iron, gold, copper, diamond, emerald, netherite, glass, stone, stone bricks, bricks, quartz and obsidian.
- Languages: English (default), Portuguese (pt_br, pt_pt) and Spanish (es_es, es_mx, es_ar, es_cl, es_uy, es_ve), generated by datagen from `data/Translations.java` and checked by `LanguageFilesTest`.
- Art: the workbench block model and textures, the GUI sprite sheet and tab icons are generated by `tools/generate_art.py` (pure Python, deterministic), which also writes `client/gui/WorkbenchSprites.java`.
- Canvas signs: plain, 16 dye colors and 2 hand-painted (`orange_purple`, `green_gradient`), each with standing and wall variants.
- Canvas item, usable as fuel (400 ticks).
- Recipes: canvas from string, canvas sign, dye recoloring from any canvas sign, and book, painting and scaffolding from canvas.
- Registry names of the canvas signs and the block entity id `moresigns:canvas_sign` are unchanged from the old 1.20.1 releases, so existing worlds keep their signs.

### Differences from the NeoForge 1.21.1 version
- Parts are item NBT (`common/sign/SignNbt.java`: tag `Part` on frame and board items, tag `SignParts` on sign items) instead of data components.
- The sign blocks apply `SignParts` in `setPlacedBy`, because the game ignores `BlockEntityTag` on signs placed by non-operators (`SignBlockEntity.onlyOpCanSetNbt`). Loot uses `copy_nbt`.
- There is no GUI sprite system in this Minecraft version, so the interface is drawn from one sprite sheet, `textures/gui/sign_workbench.png`. Positions are in the generated `client/gui/WorkbenchSprites.java`; `SpriteDrawer` does the blitting and the nine-slice.
- The access transformer (`META-INF/accesstransformer.cfg`) uses SRG names: `f_244140_` (`AbstractSignEditScreen.sign`) and `f_276451_` (`isFrontText`).
- Material tags are `forge:*` instead of `c:*`; concrete is listed as explicit blocks.

### Changed (relative to the old 1.20.1 code)
- All variants are defined in one list, `CanvasVariants`, which drives blocks, items, WoodTypes, blockstates, item models, recipes, loot, tags and lang. Data is generated with `./gradlew runData` and committed in `src/generated`.
- Each canvas variant has its own vanilla `WoodType` (`moresigns:canvas_<key>`); the vanilla sign renderer and edit screen draw them. The old custom renderer, edit screen and mixins were removed.
- Custom signs use a custom renderer (`CustomSignModel`, `CustomSignRenderer`, `CustomSignItemRenderer`). Their edit screen is swapped via `ScreenEvent.Opening` and an access transformer and draws the real sign. Hidden coplanar faces are not drawn.
- Added JUnit tests (`./gradlew test`: variant naming, text contrast, `LanguageFilesTest`) and 19 game tests (`./gradlew runGameTestServer`, including the workbench menu flows). The tests are in the test source set, so they are not in the jar.

### Fixed
- The canvas sign edit lock is now released (ticker override).
- Pick block on a custom sign returns the sign with its parts.
- Z-fighting on glass-like parts (hidden contact faces are no longer drawn).

### Removed
- Canvas Rug. The block existed without an item or textures. It is not restorable from this branch, but exists on `origin/1.20.x`.
- Forge-only template leftovers, mixins, and the JEI, CraftTweaker and AppleSkin stubs.

### Known issues
- The 19 canvas signs are separate from the custom signs and cannot be taken apart.
- Paint is a tint of the block texture (16 vanilla dyes only), so it can look muddy on blocks that already have color.
- Every material costs 1 block, whatever its rarity (a block of iron costs the same as a plank).
- Taking a sign apart with a nearly full inventory can drop one of the two parts on the ground. Nothing is lost.
- No JEI integration for the workbench.
- Gradient canvas signs have no dye recipe (creative only).
